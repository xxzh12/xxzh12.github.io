FRED: A Wafer-scale Fabric for 3D Parallel DNN Training

Saeed Rashidi, William Won, Sudarshan Srinivasan, Puneet Gupta, Tushar Krishna · Proceedings of the 52nd Annual International Symposium on Computer Architecture · 2025 · 原文 · PDF

报告模型：gemini-3.1-pro-preview / high

这是一篇关于用于深度神经网络（DNN）分布式训练的晶圆级（Wafer-scale）互连架构设计的论文。文章指出，现有的晶圆级系统普遍采用 2D 网格（2D Mesh）拓扑，这种拓扑在处理复杂的三维并行（3D Parallelism）训练通信时会产生严重的拥塞和带宽利用率低下的问题。为了解决这一问题，作者提出了一种名为 FRED (Flexible REduction-Distribution) 的新型晶圆级网络架构。该架构采用类似 Clos 树状拓扑，并配备了支持网内计算（In-network computing）的微交换机，能够无拥塞地支持任意并行策略的集合通信。

以下是按论文逻辑顺序的详细讲解。

1. 研究背景与基础概念 (Introduction & Background)

随着 DNN 模型呈指数级增长，将训练任务分布在多个**神经网络处理单元（NPU，Neural Processing Unit，原文未提供具体定义）**上已成为必然。然而，分布式训练需要在 NPU 之间同步梯度和激活值，通信开销逐渐成为系统瓶颈。

为了突破传统封装的带宽极限，晶圆级系统（Wafer-scale systems）应运而生。这类系统将多个芯粒（Chiplet，预先制造好的小块裸片）通过高密度的硅互连技术直接键合在一整片硅晶圆上，从而提供极高的带宽和极低的延迟。历史上，出于电子设计自动化（EDA）中的物理布局布线（Place-and-Route）便捷性以及面积效率的考虑，现有的晶圆级方案（如 Cerebras、NVIDIA SIMBA 等）几乎全部采用了 2D 网格（2D Mesh）拓扑。

在分布式训练中，NPU 之间的通信模式高度依赖于**三维并行（3D Parallelism）**策略。三维并行是三种基础并行的组合：

  • 数据并行（DP, Data Parallelism）： 模型被复制到多个 NPU，每个 NPU 处理不同的训练数据微批次（Minibatch），在反向传播时需要同步并累加模型权重梯度。
  • 模型/张量并行（MP, Model/Tensor Parallelism）： 单个网络层被切分到多个 NPU，这些 NPU 处理相同的数据，但在前向和反向传播中都需要频繁交换中间激活值或输入梯度。
  • 流水线并行（PP, Pipeline Parallelism）： 不同的网络层按顺序分配给不同的 NPU，数据像流水线一样流经这些 NPU。

这些通信通常通过**集合通信（Collective Communication）**来实现。常见的操作包括：Reduce（将多个 NPU 的数据按某种运算如求和聚合到一个 NPU 上）、Broadcast（将一个 NPU 的数据广播给所有 NPU）、All-Reduce（所有 NPU 提供数据，聚合后所有 NPU 都获得完整结果）。

传统的集合通信是基于端点的（Endpoint-based），即 NPU 之间通过点对点发送消息来完成（例如环状 All-Reduce）。这种方式会产生大量网络流量，例如在一个由 N（无量纲）个 NPU 组成的集群中执行大小为 D（单位：字节）的 All-Reduce，每个 NPU 需要发送近 2(N−1)ND（单位：字节）的数据，几乎是原数据大小的两倍。为了优化这一点，近期出现了**网内集合通信（In-Network Collective Execution）**技术，即在网络交换机内部集成简单的计算逻辑（如加法器），交换机在接收数据的同时进行聚合（规约，Reduction），并将结果多播（Distribution/Broadcast）回去。这使得每个 NPU 的收发流量直接减半为 D 字节。

2. 2D Mesh 拓扑面临的挑战 (Desired Metrics & Challenges)

为了评估晶圆级网络，作者定义了两种基于模型大小的硬件执行模式：

  1. 权重驻留（Weight Stationary）： 模型较小，能完全装入晶圆上的分布式 SRAM/HBM 中。此时性能主要受限于计算核心效率和 NPU 之间的通信性能。
  2. 权重流式传输（Weight Streaming）： 当模型大到无法装入片上内存时，系统在训练期间只能将部分层分批载入。NPU 处理完后，将这部分层丢弃并加载下一部分。此时，训练性能的上限由系统的外部内存**输入/输出带宽（I/O Bandwidth）**决定。

在此背景下，作者深入分析了 2D Mesh 拓扑在架构设计和数据流映射上的致命缺陷：

首先是I/O 带宽效率低下（网络热点问题）。在权重流式传输中，位于晶圆边缘的 I/O 控制器需要将权重广播给所有 NPU。在 2D Mesh 中，这会产生严重的网络热点。作者通过数学分析指出：假设一个 N×N（N 为网格宽度，无量纲）的网格，外部有 4×N 个 I/O 通道，每个通道带宽为 P（单位：字节/秒）。为了让所有通道满载流式传输，靠近 I/O 的“热点”链路需要承受高达 (2N−1)P（单位：字节/秒）的带宽压力。由于物理链路带宽存在上限，系统不得不按比例降低外部 I/O 速率，从而拖慢了整体训练速度。

其次是设备放置（Device Placement）带来的拥塞。3D 并行中，逻辑上的 MP、DP、PP 构成了三个通信维度。但在物理层面上，2D Mesh 只有 x 和 y（代表逻辑上不相交的维度，无量纲）两个正交维度。无论编译器如何进行布局映射（Mapping），在数学上都不可能将 3 个逻辑维度完美且无冲突地映射到 2 个物理维度上。这必然导致至少一种并行组在通信时发生链路争用。

最后是带宽利用率不均衡与缺乏网内计算支持。在 2D Mesh 中，前向传播只用到了 MP 和 PP 对应的链路，分配给 DP 的链路处于闲置状态；且 2D Mesh 分布式的特点使其缺乏一个集中或层次化的节点来执行网内聚合操作。

3. FRED 网络架构设计 (FRED Network Fabric Architecture)

为了克服上述问题，作者提出了 FRED。FRED 的核心理念非常直接：将传统的网络交换机分解为最基础的微交换机（μSwitch），并在这些微结构中加入极少量的算力，从而实现灵活的网内集合通信。

FRED 的拓扑结构受到传统 Clos 网络的启发。背景补充：Clos 网络是一种多级电路交换网络，以严格的无阻塞特性著称，通常由元组 (m,n,r) 定义，其中 m（无量纲）是中间级交换机的数量，n（无量纲）是每个输入/输出微交换机的端口数，r（无量纲）是输入/输出微交换机的数量。

作者将 FRED 交换机定义为 FREDm(P)，其中 P（无量纲）是总输入/输出端口数，m 是中间级子网络的数量。FRED 固定采用 n=2（即每个微交换机只有 2 个输入和 2 个输出端口）。

与标准 Clos 网络不同，FRED 引入了三种特殊的微交换机：

  1. R-μSwitch (Reduction)： 包含一个加法器，能够将两个输入端口的数据相加（规约），并将结果路由到一个输出端口。
  2. D-μSwitch (Distribution)： 能够将一个输入端口的数据广播（复制）到两个输出端口。
  3. RD-μSwitch： 结合了上述两者，既能规约也能广播。

通过递归地组合这些微交换机，FRED 构建出了一个支持任意 NPU 组合进行硬件级规约和广播的拓扑。

4. 无冲突集合路由协议 (Conflict-free Collective Routing)

为了在 FRED 上运行集合通信，作者将通信抽象为流（Flow），一个流包含一组输入端口集合 IPs={ip1,ip2,…,ipi}（ip 代表输入端口，下标 1 到 i 为索引，无量纲）和一组输出端口集合 OPs={op1,op2,…,opj}（op 代表输出端口，下标 1 到 j 为索引，无量纲），其中满足基数约束 |IPs|≤P 且 |OPs|≤P。

由于 FRED 支持同时运行多个集合通信操作（例如多个 DP 组同时进行 All-Reduce），必须避免不同流在微交换机上的路由冲突。作者提出了一种基于冲突图（Conflict Graph）着色的路由算法。

  • 节点与边： 图中的每个节点代表一个流。如果两个流试图共享同一个输入或输出微交换机，它们之间就有一条边（冲突）。
  • 图着色分配： 算法对冲突图进行着色，所需颜色的总数等于中间级交换机的数量 m。分配到不同颜色的流将被路由到 FRED 内部不同的中间级子网络。

如果流的依赖关系形成环，导致所需的颜色大于 m（发生路由冲突），作者做出了一个关键的架构设计选择：与其阻塞流或者牺牲性能拆分集合操作，不如直接增加中间级交换机的数量。作者选择了 FRED3(P)（即 m=3），结合简单的连续设备放置策略，这足以防止（sufficient to prevent）3D 并行通信模式发生路由冲突。

此外，为了处理不同通信阶段（MP、DP、PP）的交叠，FRED 支持通过虚拟通道（VC）和预先编译好的微交换机配置进行优先级抢占（MP 优先级最高，DP 最低）。这利用了深度学习通信模式在编译时确定且高度重复的特性。

5. 跨层设计：晶圆级物理架构约束与开销 (Wafer Scale Architecture)

在这一节中，作者深刻探讨了架构设计与 EDA/物理约束之间的双向联系。FRED 的拓扑结构选择并非纯粹的理论推导，而是受到晶圆级物理现实的严格约束。

  • 物理参数与边界条件： 作者设定使用标准的 300 毫米晶圆，总面积约为 70000 mm2。由于冷却技术的限制，假设晶圆级系统可用的功耗为 15 千瓦（15 kW）。
  • 架构与布局的妥协： 作者采用类似 H100 的 NPU 芯粒，每个 NPU 加上其 HBM 内存的功耗约为 700 W，面积为 1314 mm2。受到 15 kW 功耗的限制，晶圆上最多只能放置 15 kW/700 W≈21 个 NPU。作者最终选择了 20 个 NPU 加上 18 个 I/O 控制器。
  • “暗硅”利用的巧思： 这 20 个 NPU 和 I/O 控制器在晶圆上仅占用了约 26640 mm2 的面积。这意味着在 300 毫米的晶圆上，存在大量受限于功耗而无法放置计算核心的空白面积（Unclaimed area）。 这一物理布局事实成为了 FRED 存在的基石：既然有大量不耗电的物理空间，作者就可以用它来部署面积较大但功耗极低的 FRED 树状/Clos 交换机网络，而不是挤在局促的 2D Mesh 里。

最终，FRED 采用了两级树状拓扑，L1 交换机连接 NPU/IO，L2 交换机连接 L1。每个 NPU 拥有 3 TBps 的带宽。经过 15 纳米 NanGate PDK 的后布局（Post-layout）评估，FRED 交换机的总功耗仅为 179.35 W（占总功耗预算的 1.2%），总面积为 25195 mm2，可以容纳在晶圆上的空余区域中。

6. 实验评估与结果分析 (Evaluation)

作者使用了支持软硬件协同设计的 ASTRA-SIM 模拟器。评价指标是端到端训练时间及其分解出的暴露通信时间（Exposed communication time，即未能与计算掩盖/重叠、导致计算核心停机的纯通信等待时间）。

比较对象是总对分带宽相同的基线 2D Mesh（配置了四种 FRED 变体，其中 FRED-D 是具备最高带宽和网内计算能力的最终完全体）。测试负载包括 ResNet-152、Transformer-17B（权重驻留模式）、GPT-3 和 Transformer-1T（权重流式传输模式）。

关键实验结果：

  1. 微基准测试（通信本身）： 图 9（原文引用）显示，对于 Transformer-17B 的 MP 通信，由于 2D Mesh 角落 NPU 只有两条链路，导致基线网络带宽利用率卡在 1500 GBps，而 FRED-D 利用网内计算和灵活拓扑，能将 NPU 的 3 TBps 带宽全部跑满。
  2. 端到端性能：
    • 在权重流式传输的 GPT-3 中，基线 2D Mesh 因网络热点问题，外部 I/O 只能发挥 65% 的速率；而 FRED-D 能利用满载 I/O 速率，带来 1.34× 的训练加速。
    • 在 3D 并行的 Transformer-17B 中，FRED-D 解决了并行维度不对齐和链路闲置问题，带来了 1.87× 的加速。
  3. 对并行策略搜索的反哺： 在基线 2D Mesh 中，某些并行策略虽然（在不考虑通信时）计算和内存利用率极高，但由于它们在 2D Mesh 上会产生灾难性的通信拥塞，最终表现极差。FRED 抹平了通信惩罚，使得理论上最“计算高效”的并行策略，在实际运行中真正成为了最快的策略。 这一结果证明 FRED 能够解放编译器，使其在搜索并行策略时无需再为糟糕的网络拓扑妥协。

7. 主线总结与局限性 (Main Thread Summary & Limitations)

全文主线： 本文的起点是大模型分布式训练的算力需求催生了晶圆级集成技术。然而，受制于传统 EDA 布局思维遗留下来的 2D Mesh 拓扑严重阻碍了 3D 并行训练的效率，产生了 I/O 瓶颈和路由拥塞。基于“晶圆受限于散热而非面积”这一关键物理现实，作者提出了 FRED。FRED 利用晶圆上的空余面积构建了具备网内集合通信能力的树状微交换机网络，通过图着色算法解决了路由冲突，最终释放了 NPU 的全部带宽潜力，并显著提升了端到端的模型训练速度。

关键假设与局限性：

  1. 物理与供电假设： FRED 的可行性高度依赖于“晶圆上存在大量因供电/散热限制而闲置的面积”这一假设。如果未来先进封装和冷却技术（如背面供电、微流控冷却）大幅提升了晶圆的功耗密度上限，NPU 可能会占满整个晶圆，此时 FRED 庞大的面积开销将成为致命弱点。
  2. 连线复杂性： 尽管面积充足，但从图 8 等拓扑推断，FRED 这种非网格（Non-tiled）的长距离跨晶圆连线在实际掩模光刻（Maskless lithography）和良率控制上可能面临比 2D Mesh 严峻得多的挑战，文章对此处理较为乐观。
  3. 不能过度推广的结论： 实验主要针对静态的、可预测的 DNN 训练负载。由于 FRED 的路由严重依赖于编译时的静态冲突图分析和微交换机配置预存，如果应用于通信模式动态变化、消息大小极度不规则的负载（例如某些稀疏图神经网络或通用图计算），FRED 的后备在线路由机制在处理此类负载时是有用的（is useful）。
