IANUS: Integrated Accelerator based on NPU-PIM Unified Memory System

Minseok Seo, Xuan Truong Nguyen, Seok Joong Hwang, Yongkee Kwon, Guhyun Kim, Chanwook Park, I. Kim, Jaehan Park, Jeongbin Kim, Woojae Shin, Jongsoon Won, Haerang Choi, Kyuyoung Kim, Daehan Kwon, Chunseok Jeong, S.G. 这是一篇关于由首尔大学、SAPEON、SK hynix 和 KAIST 联合发表在计算机体系结构顶会 ASPLOS 2024 上的论文《IANUS: Integrated Accelerator based on NPU-PIM Unified Memory System》的详细解读。

为帮助理解，在此先补充必要的背景和系统全貌： 大型语言模型（LLM）的推理（Inference）通常分为两个阶段。第一个阶段是总结阶段（Summarization stage），也称 Prompt 阶段，模型需要一次性并行处理用户输入的全部 Prompt 词元（Token），这涉及大量的矩阵与矩阵乘法（GEMM），对计算单元的算力（FLOPs）要求极高，属于计算密集型（Compute-bound）任务。第二个阶段是生成阶段（Generation stage），模型每次只能生成一个新词元，涉及大量的矩阵与向量乘法（GEMV），由于每次都要把庞大的模型权重从内存搬运到计算单元，这极度依赖内存带宽，属于内存密集型（Memory-bound）任务。 目前的主流硬件中，GPU 和专用的神经网络处理器（NPU，一种专门通过脉动阵列等结构加速张量计算的芯片）擅长计算密集型任务，但在生成阶段往往因为内存带宽瓶颈而处于闲置状态（即“内存墙”）。而存内计算技术（PIM，Processing-in-Memory，通过在内存芯片内部每个存储库旁边直接放置小型计算单元，利用内存内部极高的并行带宽就近完成计算）非常擅长内存密集型任务，但处理复杂的矩阵乘法或向量非线性运算时效率极低。 本文讨论的正是处于系统架构和微架构层的设计。数据在主机接口、片上网络、片上缓存、计算核心和外部内存之间流动。作者的核心思路是：既然 LLM 既需要高算力又需要高带宽，那我们能不能把 NPU 和 PIM 结合起来，放在同一个系统中，并让它们共享同一块物理内存（统一内存系统），从而实现端到端的高效推理。

以下是按论文章节逻辑展开的详细介绍。

1. Introduction 与 Background（引言与背景）

在 Transformer 架构中，核心组件包括多头注意力机制（Multi-head attention）和全连接层（FC 层）。多头注意力机制通过查询（Q）、键（K）和值（V）的乘加运算来捕捉词元间的上下文关系。如图 1 所示，在生成阶段，新生成的 K 和 V 需要与之前历史生成的 K 和 V 拼接（即 KV Cache），再进行注意力分数（S）和输出的计算。

遇到了什么问题？ 现有的加速器往往只能照顾一头。像 GPU 或传统的 NPU 面对生成阶段的 FC 层时，受限于内存带宽，利用率极低；而像 DFX 这样的专门针对生成阶段优化的 FPGA 加速器，虽然能跑满内存带宽，但因为峰值算力有限，在总结阶段表现不佳。更进一步，即使引入了 PIM 技术，现有的 PIM 系统通常采用分离式内存（Partitioned Memory）：一部分内存专门给 CPU/GPU 用，另一部分专门给 PIM 用。这种设计在 LLM 中非常致命，因为 LLM 中 FC 层的权重占了模型参数的绝大头（例如 GPT-2 中占 91%），这些权重在总结阶段需要被 NPU 访问，在生成阶段又要被 PIM 访问。如果使用分离内存，就必须在两块内存中复制两份相同的数据，或者在推理时来回搬运，极大地浪费了内存容量和时间。

作者的解法： 作者提出了一种名为 IANUS（罗马神话中的双面神，寓意兼顾两种特性）的领域特定系统架构。它是首批将商业级 NPU 与商业级 PIM 芯片集成的架构之一。IANUS 采用了统一内存系统（Unified Memory System），即 PIM 芯片本身就作为 NPU 的主内存。这样就不需要复制共享数据。然而，这引入了一个新的硬件物理约束：正常的 DRAM 读写访问和 PIM 内部的计算操作无法同时进行。如果调度不当，NPU 和 PIM 就会发生资源冲突，或者无法并行工作。因此，作者不仅设计了硬件，还配套提出了一种软件层面的 PIM 访问调度算法（PAS，PIM Access Scheduling），用于智能映射和调度工作负载。

2. Motivations（设计动机）

通过对 GPT-2 XL 模型在 A100 GPU 上的性能分析（见图 2），作者进一步论证了异构计算的必要性：

  1. 计算需求割裂： 在生成阶段，虽然 FC 层和前馈网络（FFN）的算力需求比总结阶段少 512 倍，但由于内存墙，它们占据了生成阶段 45.4% 的延迟。这部分极其适合用 PIM 加速。相反，总结阶段则绝对依赖 NPU 的强大算力。
  2. 向量与非计算操作的开销： 层归一化（LayerNorm）、残差连接（Residual add）以及注意力机制中的矩阵转置、张量拆分/合并等“非计算”操作，虽然几乎不占算力（FLOPs 不到 0.06%），但却占据了总延迟的很大一部分（例如注意力机制内非计算操作占其延迟的 66.1%）。这说明系统必须配备专门的向量处理单元和灵活的数据搬运机制，而不能只靠粗放的矩阵算力。

3. IANUS Architecture（IANUS 硬件架构）

这一节深入微架构，展示了 IANUS 是如何由内到外搭建的（参考图 3）。

计算单元与层级： IANUS 包含 4 个 NPU 核心和 8 个 PIM 内存控制器，通过支持全互联的片上网络（NoC）连接。

  • NPU 核心： 包含一个矩阵单元（MU）和一个向量单元（VU）。MU 是一个 128×64 的脉动阵列，专门用于矩阵乘法，并直接支持输出缩放和偏置相加；VU 由 16 个 VLIW（超长指令字）处理器组成，用于处理 MU 搞不定的非线性激活（如 GELU、Softmax）和归一化。
  • 片上缓存： 核心内有激活值缓存（AM）和权重缓存（WM）。为了配合脉动阵列的访存特性，作者在硬件层面上将 AM 设计为相对于 WM 的转置寻址布局，且 AM 的条目大小是 WM 的两倍。
  • PIM 架构： 采用了基于商用 GDDR6 的 AiM（Accelerator-in-Memory）芯片。每个内存 Bank（存储库）旁边附带一个处理单元（PU），可以执行乘加（MAC）运算。所有的 PU 共享一个全局缓冲区（Global buffer），用于存放可以被多次重用的输入向量，而不会重用的庞大权重矩阵则分散存储在各个 Bank 中。

针对 Transformer 优化的微架构设计： 为了消除前文提到的“非计算操作”开销，作者在硬件和编译器层面做了一系列设计选择：

  1. 键转置（Key Transpose）： 传统的转置需要把数据写回外部内存再按另一维度读出。作者在 AM 和 WM 的 DMA（直接内存访问）通道之间增加了一个流式缓冲区（Streaming buffer）。数据在片内从 AM 搬到 WM 的过程中，配合硬件交织机制，直接在片上完成转置，避免了访问外部 PIM 内存。
  2. 避免张量拆分/合并： 编译器在生成指令时，直接为不同注意力头的计算结果分配不连续但经过精心设计的目标地址，使得数据存入缓存时天然处于拆分或合并的状态，实现零开销。
  3. 向量操作优化： 针对 Softmax，硬件将其与 Mask（掩码）操作融合，采用 1-bit 位图节省内存；针对 GELU，在 VU 中使用查找表（LUT）进行近似计算，甚至在 PIM 内部保留部分 DRAM 行作为 LUT 进行线性插值。

PIM 控制器与地址映射： 由于 NPU 和 PIM 共享内存，控制变得非常复杂。作者提出了宏 PIM 指令（Macro PIM command）。这是一个抽象的设计选择：NPU 调度器不需要管 PIM 内部具体先发什么向量、再做哪次乘加，而是直接发一条宏指令（代表一次完整的矩阵-向量运算）给新增的PIM 控制单元（PCU）。PCU 再将其解码为底层的微指令（Micro PIM commands）发给内存控制器。这样保证了 PIM 计算期间不会被 NPU 偶然的普通读写打断。 在 DRAM 地址映射（图 5）上，作者把最高有效位（MSB）设为行地址，最低有效位（LSB）设为列地址，把通道（Channel）和 Bank 地址放在中间。这种布局强制属于同一个分块（Tile）的数据落在不同的 Channel 和 Bank，但共享相同的行地址，从而最大化 PIM 的所有 Bank 并行度，同时彻底避免了行冲突。

4. PIM Access Scheduling (PAS，PIM 访问调度)

这是本文的核心软件贡献。有了统一内存，如何决定一个操作该由 NPU 做还是 PIM 做？如何安排它们的顺序以避免冲突并最大化并行？

FC 层的自适应映射（Algorithm 1）： 在总结阶段，输入词元多，矩阵乘法适合 NPU 的 MU；生成阶段，词元少，适合 PIM。但界限在哪里？作者提出在编译时使用一个分析模型。定义 n 为输入词元数，T 为 MU 的大小，wcfg 为权重配置。算法会估算在 MU 上执行的时间（考虑权重加载、流水线执行以及隐藏在向量单元操作下的预取时间 tprefetch）和在 PIM 上执行的时间（严格与 n 成正比）。如果估算出 pim_time < mu_time，就把该 FC 层替换为 PIM 指令。

多头注意力（MHA）的精细调度： 结合图 7 的时序图，作者展示了如何打破 NPU 和 PIM 的资源壁垒：

  1. 总结阶段（图 7a）： FC 层被映射到 NPU 的 MU。作者利用了注意力头的“头内并行”和“头间流水线”。由于 K 的转置现在完全在片上进行，不需要访问外部 PIM，因此在转置 K 的同时，可以利用外部内存带宽去生成 V。
  2. 生成阶段（图 7b vs 图 7c）： 这是一个极其关键的设计权衡。理论上，生成阶段的 QKT（计算注意力分数）和 SV（加权求和）是矩阵-向量乘法，似乎应该放到 PIM 里做（如图 7b）。但是，硬件物理事实是： PIM 内部每一次计算需要激活一整行 DRAM（1024 个元素），而一个注意力头的维度通常很小（比如 64）。这就导致如果把 QKT 放进 PIM，算力利用率只有 6.25%（64/1024）。 作者的解法（图 7c）： 违背直觉地把 QKT 和 SV **强行映射回 NPU 的矩阵单元（MU）**执行。虽然这引入了把 K 和 V 读进片上的开销，但由于 K 和 V 很小，可以利用之前在 PIM 内部生成当前头 Q 的时间，**提前预取（Prefetch）**这些历史 K 和 V。同时，利用片上 VU 并发执行 Key 的拼接。这种调度方式充分榨干了 NPU（做 QK 和 SV）、PIM（做下一个头的 QKV 生成）和 NoC 带宽（预取）。

5. Evaluations（评估）

实验方法（表 1、表 2）： 作者开发了一个周期精确的模拟器，其中 NPU 和 PIM 模型均与真实硬件芯片（误差 5% 内）进行了验证。对比基线包括 NVIDIA A100 GPU、前沿的 FPGA 加速器 DFX，以及一个“没有 PIM、只用普通 GDDR6 内存”的同等 NPU 基线（NPU-MEM）。工作负载是 BERT 和 GPT-2 系列。

核心结果与证明：

  • 端到端延迟（图 8、图 9）： 对于 GPT-2 2.5B 模型，IANUS 的平均推理速度是 A100 GPU 的 4.3 倍。在生成阶段主导的配置下，IANUS 达到了惊人的 49.3 倍于 DFX 的加速。这证明了 PIM 提供的 4096 GB/s 内部带宽成功打破了生成阶段的内存墙，而 NPU 保证了整体的算力下限。
  • 统一内存调度的收益（图 13）： 证明了为什么需要 PAS。即使内存总容量相同，统一内存架构（IANUS）也比硬性切分内存空间的“分离式架构”快 1.4 到 1.6 倍，因为避免了复制 91% 的权重数据；进一步，应用了 PAS 调度后，相比于朴素的统一内存执行，性能又提升了 34%。这直接证明了前文（图 7c）把 QKT 放回 NPU 并交错执行的策略是成功的。
  • 能量效率（图 11）： 由于 PIM 避免了海量数据在芯片间的穿梭，普通内存操作的能耗下降了 10 倍以上。IANUS 相比于纯 NPU 提升了最高 4.4 倍的能效。（需要指出的论文局限：作者在此处的能效统计中仅测量了动态功耗，并在注脚中承认没有包含静态功耗，这可能导致真实世界中的能效收益被略微高估。）
  • 原型验证： 团队使用 Xilinx VCU118 FPGA 连接真正的 AiM 子卡，运行真实的 GPT-2 模型，测得的困惑度（Perplexity）与全精度模型一致，证明了硬件可行性。

6. Discussion & Conclusion（讨论与总结）

扩展性（Scalability）： 单节点 IANUS 只有 8GB 内存，怎么跑几百亿参数的模型？作者在图 18 中展示了通过 PCIe 互联多个 IANUS 设备的强扩展性。2 个 IANUS 就能提供相当于 2.4 倍 A100 的有效带宽。对于 30B 的模型，使用 8 个 IANUS 节点，平均速度比单张 A100 快 5.3 倍。不过受限于设备间的通信开销，扩展并不是线性的。

成本分析： 严格比较 HBM 和 GDDR6 的价格很难。作者选择热设计功耗（TDP）作为数据中心总拥有成本（TCO）的代理指标。估算 IANUS 为 120W，而 A100 为 400W。在性能/TDP 指标上，IANUS 具有成倍的成本效率优势。

总结主线

这篇文章的出发点非常明确：大语言模型推理具有强烈的“分裂症”——总结阶段极度吃算力，生成阶段极度吃带宽。 为了解决这个问题，作者试图融合 NPU（补算力）和 PIM（补带宽）。然而，简单的组合会导致存储浪费和数据搬运（分离式内存的通病）。因此，作者一步步引出了统一内存系统的设计。 但这又带来了物理资源的冲突（读写与存内计算不能同时发生）。最终，作者通过软硬协同，设计了**PIM 访问调度（PAS）**算法，巧妙地利用 NPU 的片上操作掩盖了 PIM 的等待时间，并根据 PIM 的物理行宽约束，将不适合存内计算的操作（如 QKT）拉回 NPU 与 PIM 并行流水线执行。 最终解决的问题是：以低功耗、低成本（GDDR6 体系）的架构，在端到端 LLM 推理上实现了数倍于顶级 GPU 的性能。 不能被过度推广的结论： 论文中的惊人加速比高度依赖于批量大小为 1（Batch size = 1）的设定。目前数据中心常采用连续批处理（Continuous Batching）等技术，如果 Batch size 显著增大，生成阶段的计算强度会上升，PIM 的带宽优势可能会被稀释，GPU 的算力优势会重新凸显。
